# План і дії студентів для підготовки до CTF

> Версія: 1.0  
> Оновлено: 5 вересня 2026  
> Навантаження: дві командні зустрічі по 2 години + 2–3 години самостійної практики

## 1. Що потрібно вміти до змагання

Не потрібно знати всю кібербезпеку. Потрібно вміти:

- зрозуміти, що дали в задачі;
- визначити ймовірну категорію;
- перевірити кілька базових гіпотез;
- користуватися пошуком, документацією та простими інструментами;
- записувати зроблені кроки;
- попросити конкретну підказку;
- перейти до іншої задачі, якщо прогресу немає;
- пояснити, як отримано flag.

Мінімальна особиста ціль: **4–5 самостійно розв'язаних beginner-задач до 18 вересня**.

## 2. Зустріч №1 — 2 години

### 0:00–0:15 — знайомство з форматом

Після вступу кожен має розуміти:

- Jeopardy CTF — це дошка незалежних задач за бали;
- flag — спеціальний рядок, наприклад `picoCTF{...}`;
- дозволено працювати лише з тим, що належить до задачі й дозволено правилами;
- головне — експериментувати, перевіряти гіпотези й комунікувати.

### 0:15–0:30 — демонстрація

Тренер показує одну дуже просту задачу. Завдання студентів — помічати не лише команди, а послідовність думок:

> ознака → гіпотеза → перевірка → результат.

### 0:30–0:55 — задача всією групою

Група отримує файл або закодований текст і відповідає:

1. Що це може бути?
2. Які три найдешевші перевірки?
3. Які результати підозрілі?
4. Де може ховатися flag?

### 0:55–1:10 — розподіл напрямів

Кожен повідомляє, що вже вміє:

- програмування/Python;
- Linux/термінал;
- HTML, JavaScript, HTTP;
- Git;
- мережі;
- робота з файлами/зображеннями;
- пошук інформації та англійська.

На основі цього обирається основна і додаткова категорія.

### 1:10–1:50 — перша індивідуальна задача

Кожен працює над власною easy-задачею. Через 15 хвилин без прогресу треба:

- записати, що вже перевірено;
- поставити конкретне питання;
- взяти hint або змінити задачу.

### 1:50–2:00 — домашня практика

Кожен отримує 4–6 задач і шаблон короткого writeup.

## 3. Самостійна практика — 2–3 години

### Спільний мінімум для кожного

| Задача | Напрям | Приклад навички |
|---:|---|---|
| 1 | General Skills / Linux | `cat`, `grep`, `strings`, пошук файла |
| 2 | Encoding / Crypto | Base64, Hex, Caesar або простий XOR |
| 3 | Forensics | тип файла, metadata, вбудований текст |
| 4 | Власна спеціалізація | Web / OSINT / Network |
| 5 | Власна спеціалізація | трохи складніша задача того самого типу |

Шоста задача — додаткова, якщо п'ять виконані швидко.

### Де тренуватися

- Усі: [picoCTF / picoGym](https://picoctf.org/get_started.html) і [CTFlearn](https://ctflearn.com/).
- Якщо слабко з Linux: [OverTheWire Bandit](https://overthewire.org/wargames/bandit/), перші рівні.
- Основна роль Web: beginner-лаби [PortSwigger Web Security Academy](https://portswigger.net/web-security).
- Основна роль Forensics/Network: beginner-лаби [CyberDefenders](https://cyberdefenders.org/blue-team-labs/) після простих задач picoCTF.

Не потрібно хаотично стрибати між п'ятьма платформами. Основна — picoCTF; інші потрібні лише під конкретну слабку навичку.

## 4. Як розв'язувати кожну задачу

### Крок 1. Розвідка

Запиши:

- назву і категорію;
- умову своїми словами;
- що саме дали;
- формат очікуваного flag;
- hints і файли.

### Крок 2. Базові перевірки

Для файла:

```bash
file filename
strings filename | head -n 50
exiftool filename
xxd filename | head
```

Для Web:

- View Page Source;
- DevTools: Elements, Sources, Network, Application/Storage;
- JavaScript-файли;
- `robots.txt`;
- параметри URL, cookies, response headers.

Для дивного тексту:

- чи схоже на Base64, Hex або URL encoding;
- CyberChef Magic;
- частотність і підказки в умові.

### Крок 3. Таймбокс

Якщо 10–15 хвилин немає нової інформації:

1. Запиши негативні результати.
2. Перечитай умову й hint.
3. Сформулюй одне конкретне питання для пошуку або AI.
4. Попроси підказку або перейди до іншої задачі.

### Крок 4. Після отримання flag

Не закривай задачу одразу. Запиши ключовий патерн і повтори вирішальний крок без writeup.

## 5. Шаблон короткого writeup

Скопіюй для кожної задачі:

```markdown
### Назва задачі

- Посилання/платформа:
- Категорія і складність:
- Що дали:
- Що треба було знайти:
- Перша гіпотеза:
- Що перевірив:
- Ключова знахідка:
- Інструмент або команда:
- Як отримав flag, без самого flag:
- Де застряг і яку підказку використав:
- Який патерн запам'ятав:
```

Не публікуй чинні flags або паролі активних інстансів у спільному відкритому документі.

## 6. Як правильно користуватися Google та AI під час навчання

Хороші запити:

```text
CTF PNG first checks file strings exiftool
How to identify Base64 versus hex in a CTF?
Wireshark how to follow an HTTP TCP stream
Explain what this command output means; do not give me the flag
Give me one hint for the next diagnostic step, not the solution
```

Поганий запит:

```text
Solve this task and give me the flag
```

Правило: будь-яку команду від AI треба зрозуміти перед запуском. Не запускати команди, що видаляють файли, змінюють систему або завантажують/запускають невідомий код.

На самому турнірі користуватися AI, Google і writeups можна лише відповідно до офіційних правил організатора.

## 7. Зустріч №2 — 2 години

### 0:00–0:25 — обмін досвідом

Кожен за 3–5 хвилин показує одну задачу:

- що дали;
- яка була ключова ознака;
- що спочатку не спрацювало;
- як знайшов рішення;
- який патерн має запам'ятати команда.

### 0:25–1:20 — mock CTF

Правила репетиції:

- одна година або 55 хвилин;
- 8–10 простих задач різних категорій;
- перші 5 хвилин — тільки огляд і розподіл;
- у спільних нотатках є власник задачі, статус і знахідки;
- 10–15 хвилин без прогресу — задача повертається в пул або передається;
- перші 40 хвилин тренер не дає технічних підказок.

### 1:20–1:40 — розбір

Команда відповідає:

- які задачі обрала першими й чому;
- де було дублювання роботи;
- де загубили час;
- які нотатки допомогли іншому учаснику;
- яку одну зміну внесемо в тактику.

### 1:40–2:00 — тактика й техніка

- підтвердити ролі;
- перевірити ноутбуки, зарядки, admin rights і OpenVPN;
- відкрити всі потрібні програми;
- погодити формат спільних нотаток;
- уточнити час і місце збору.

## 8. Формат спільних нотаток на CTF

| Задача | Категорія / бали | Хто працює | Статус | Що перевірено | Знахідки / наступний крок |
|---|---|---|---|---|---|
|  |  |  | Не почато |  |  |

Статуси: `Не почато`, `Працюю`, `Застряг`, `Передано`, `Розв'язано`.

## 9. Особистий чекліст на 17 вересня

- [ ] Я виконав щонайменше 4–5 задач.
- [ ] Я можу без writeup пояснити дві задачі.
- [ ] Я знаю свою основну й додаткову категорію.
- [ ] Я знаю 5–10 базових команд/перевірок для своєї категорії.
- [ ] Ноутбук заряджений і має права адміністратора.
- [ ] OpenVPN та потрібний софт встановлені.
- [ ] Я маю зарядку, мишку за потреби, воду й блокнот.
- [ ] Я знаю час і місце збору.

## 10. Правила поведінки команди

- Говоримо про знахідки, а не працюємо мовчки.
- Не висміюємо прості питання й помилки.
- Не видаємо припущення за факт.
- Не запускаємо небезпечні команди або файли на чужих системах.
- Не атакуємо інші команди, платформу чи сторонні сайти.
- Не крадемо flags і не ділимося ними поза командою.
- Після невдачі залишаємо нотатки, щоб наступний учасник не повторював ті самі кроки.
