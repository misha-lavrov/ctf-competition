# План і дії тренера CTF-команди

> Версія: 1.0  
> Оновлено: 5 вересня 2026  
> Роль: тренер-координатор і, за потреби, п'ятий учасник

## 1. Твій очікуваний результат

За 2–3 години не потрібно «вивчити кібербезпеку». Потрібно самому пройти цикл:

> прочитав задачу → визначив тип → перевірив базові гіпотези → знайшов або декодував flag → пояснив рішення іншій людині.

З твоїм досвідом Senior Java Backend Engineer найближчими зонами будуть Web/HTTP, Git, General Skills, нескладні скрипти та координація. Forensics, базове Crypto й Network треба освоїти на рівні типових перших перевірок.

## 2. Інтенсив тренера на 2 години 45 хвилин

### Блок 1. Формат і мислення — 20 хв

Прочитай розділи 1–4 у [спільному конспекті](03_CTF_конспект.md) і переконайся, що можеш без підглядання пояснити:

- що таке CTF, Jeopardy і flag;
- чим Web відрізняється від Forensics, Crypto, OSINT і Network;
- чому не можна 40 хвилин мовчки сидіти над однією задачею;
- чому writeup корисний після власної спроби, але не замінює розуміння.

### Блок 2. П'ять практичних патернів — 90 хв

Не витрачай більше 15–20 хвилин на одну задачу. Якщо застряг — візьми hint, постав точне запитання AI або проглянь лише наступний крок у writeup, після чого закрий його і повтори сам.

| № | Напрям | Що відпрацювати | Орієнтир часу |
|---:|---|---|---:|
| 1 | General Skills | знайти flag у файлі через `cat`, `grep`, `strings` | 10–15 хв |
| 2 | Encoding/Crypto | розпізнати Base64 або Hex і декодувати в CyberChef/терміналі | 10–15 хв |
| 3 | Forensics | перевірити тип файла, `strings`, metadata, розширення | 15–20 хв |
| 4 | Web | переглянути source, DevTools, JS, cookies, `robots.txt`, Network | 20 хв |
| 5 | Git | пройти `MY GIT` або аналог: README → локальні `user.name`/`user.email` → commit/push | 20 хв |

Рекомендовані платформи:

- [picoCTF / picoGym](https://picoctf.org/get_started.html) — головна;
- [CTFlearn](https://ctflearn.com/) — прості beginner-задачі;
- [OverTheWire Bandit](https://overthewire.org/wargames/bandit/) — Linux і термінал;
- [PortSwigger Web Security Academy](https://portswigger.net/web-security) — для поглиблення Web;
- [CyberDefenders](https://cyberdefenders.org/blue-team-labs/) — для Forensics/Network після бази.

### Блок 3. Мінімальний інструментарій — 30 хв

Виконай або хоча б перевір на тестових файлах:

```bash
file sample
strings sample | head
grep -Rni "flag" .
xxd sample | head
base64 -d encoded.txt
curl -i https://example.com/
git log --oneline --all --decorate
git status
```

Відкрий і знайди основні елементи:

- Browser DevTools: Elements, Sources, Network, Application/Storage;
- CyberChef: From Base64, From Hex, Magic;
- Wireshark: display filter, HTTP/DNS, Follow TCP Stream.

Не треба зараз глибоко вчити Burp Suite, Ghidra, buffer overflow або асемблер. Достатньо знати, для чого вони існують.

### Блок 4. Репетиція пояснення — 25 хв

Обери одну розв'язану задачу й поясни її вголос за схемою:

1. Що дали?
2. Який факт був підозрілим?
3. Яку гіпотезу перевірив?
4. Який інструмент використав і чому?
5. Як отримав flag?
6. Який загальний патерн можна перенести на інші задачі?

Після цього розв'яжи ще одну просту задачу з таймером на 10 хвилин так, ніби студенти дивляться на екран.

## 3. Підготовка середовища

### Обов'язкове

- [ ] Chrome або Firefox.
- [ ] OpenVPN-клієнт.
- [ ] Права адміністратора.
- [ ] Git.
- [ ] Python 3.
- [ ] 7-Zip або аналогічний архіватор.
- [ ] Текстовий редактор, наприклад VS Code.

### Бажане

- [ ] WSL2 з Ubuntu або окрема Linux VM.
- [ ] Wireshark.
- [ ] ExifTool.
- [ ] CyberChef у закладках.
- [ ] `binwalk` у Linux.

Невідомі виконувані файли не запускай безпосередньо на основній системі. Для них потрібне ізольоване середовище; у вашому короткому курсі такі задачі можна пропускати.

## 4. Підготовка до зустрічі №1

- [ ] Пройти щонайменше 4 різні easy-задачі.
- [ ] Вибрати одну Base64/General задачу для короткої демонстрації.
- [ ] Вибрати одну Forensics-задачу для групової роботи.
- [ ] Підготувати посилання на 4–6 beginner-задач для кожного студента.
- [ ] Створити спільний чат і документ/таблицю прогресу.
- [ ] Зібрати інформацію про навички та ноутбуки кандидатів.
- [ ] Уточнити правила турніру щодо Google, AI, writeups, власних нотаток та кількості ноутбуків.

### Сценарій живої демонстрації

Не приховуй помилки. Проговорюй мислення:

> «Я бачу незрозумілий рядок. Символи й знак `=` наприкінці схожі на Base64. Перевірю цю гіпотезу в CyberChef. Отримав читабельний текст і flag. Отже, важливо не вгадувати, а впізнати ознаки формату й перевірити припущення».

## 5. Як допомагати студенту, не розв'язуючи за нього

Став запитання по сходинках:

1. Що саме тобі дали: текст, URL, файл, архів, код чи мережевий дамп?
2. Яка категорія і що зазвичай у ній перевіряють?
3. Що ти вже зробив? Покажи команди та результати.
4. Що в результатах виглядає незвично?
5. Яка одна наступна гіпотеза?
6. Якою найпростішою дією її перевірити?

Рівні підказки:

- рівень 1 — нагадати категорію або чекліст;
- рівень 2 — назвати інструмент;
- рівень 3 — назвати потрібну функцію/команду без готових параметрів;
- рівень 4 — показати один крок, а решту студент повторює сам;
- готове рішення — тільки під час фінального розбору.

## 6. Перевірка самостійної роботи

Не перевіряй лише наявність flag. Для двох задач кожен студент має усно або письмово відповісти:

- що було дано;
- як визначив напрям;
- які дві гіпотези перевірив;
- яка команда або дія стала ключовою;
- що зробив би швидше наступного разу.

Ознаки розуміння:

- студент може повторити рішення без writeup;
- пояснює, навіщо була команда;
- розрізняє спостереження і припущення;
- переносить патерн на схожу задачу.

Ознаки механічного копіювання:

- не може пояснити параметри команди;
- називає лише послідовність кліків;
- AI/writeup одразу дав готовий flag;
- без того самого тексту підказки не може повторити шлях.

## 7. План роботи між зустрічами

Твій час перевірки можна вкласти приблизно в 45–60 хвилин:

- 10 хв — переглянути таблицю прогресу;
- 20–30 хв — відповісти на конкретні тупики;
- 10 хв — визначити типові помилки для розбору;
- 10 хв — підготувати 8–10 задач для mock CTF.

Домовся, що студент пише не «не виходить», а:

```text
Задача і посилання:
Що дали:
Що вже перевірив:
Результат команд:
Моя поточна гіпотеза:
На якому кроці потрібна підказка:
```

## 8. Твоя роль на mock CTF

Перші 40 хвилин:

- не розв'язуй задачі за студентів;
- спостерігай, хто обирає задачі, чи є дублювання і чи ведуться нотатки;
- втручайся тільки при технічній проблемі або небезпечній дії.

Останні 15–20 хвилин:

- дозволь команді попросити одну структуровану підказку на задачу;
- зафіксуй, де втрачено час;
- обговори не тільки flags, а й процес.

## 9. Якщо ти входиш до складу команди

Твої функції:

- швидкий огляд усіх задач і розподіл;
- General Skills, Git, нескладний Web/HTTP, кодування та Python;
- синхронізація кожні 15–20 хвилин;
- контроль таймбоксів;
- допомога з формулюванням пошукових запитів;
- ведення загального журналу.

Не забирай усі прості задачі. Студенти повинні мати власні завершені розв'язання й особистий досвід успіху.

## 11. Наступний крок після змагання

Протягом 2–3 днів провести 30-хвилинний розбір:

- скільки задач відкрили, почали й завершили;
- де втратили найбільше часу;
- які інструменти спрацювали;
- які 2–3 категорії тренувати далі;
- чи варто зробити CTF-напрям частиною гуртка.
